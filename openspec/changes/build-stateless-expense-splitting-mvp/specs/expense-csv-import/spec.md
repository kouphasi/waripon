## Purpose

現在の計算内容を変更する前に不正なデータを検出しながら、持ち運び可能なCSVファイルからグループの支払い明細を読み込めるようにします。

## ADDED Requirements

### Requirement: 定義済みの支払いCSV形式を受け付ける
システムは、`description`、`amount`、`paid_by`、`split_among` の各列を持つUTF-8のCSVファイルを受け付けなければならない（SHALL）。`split_among` には、`|` で区切った1人以上の参加者名を格納する。

#### Scenario: 有効なCSVファイルを解析する
- **WHEN** すべての行に説明、正の整数円の金額、支払者名、1人以上の負担者名が含まれている
- **THEN** システムは各行を支払いとして解析し、最初に出現した順序で重複のない参加者一覧を生成する

#### Scenario: 引用符付きCSVフィールドを扱う
- **WHEN** カンマまたは引用符を含む有効なフィールドが標準的なCSVの引用方法を使用している
- **THEN** システムは意図された値を変更せずにそのフィールドを解析する

#### Scenario: UTF-8のバイトオーダーマークを受け付ける
- **WHEN** その他の点では有効なCSVファイルの先頭にUTF-8のバイトオーダーマークが存在する
- **THEN** システムはそのマーカーを無視してヘッダーを正しく認識する

### Requirement: インポートするCSVデータを検証する
システムは、計算状態を変更する前にCSV全体を検証しなければならない（SHALL）。インポートできない行がある場合は、元ファイルの行番号とともにエラーを報告しなければならない（SHALL）。

#### Scenario: 無効な行を報告する
- **WHEN** 必須値の欠落、無効な金額、空の負担者一覧、負担者名の重複、または不正なCSV構文を含む行がある
- **THEN** システムは行番号と理由を報告し、どの行もインポートしない

#### Scenario: 対応していないヘッダーを拒否する
- **WHEN** CSVヘッダーに必須列がない、または同じ列が重複している
- **THEN** システムはヘッダーの問題を報告し、現在の計算内容を変更しない

#### Scenario: 参加者への参照を正規化する
- **WHEN** 支払者名または負担者名の前後に空白が含まれている
- **THEN** システムは照合前に名前の前後を除去し、空文字列になった名前を拒否する

### Requirement: CSVによる置き換えをプレビューして確認する
システムは、解析した参加者と支払いのプレビューを表示し、現在の計算データを置き換える前に確認を求めなければならない（SHALL）。

#### Scenario: 有効なプレビューを確定する
- **WHEN** ユーザーが有効なCSVプレビューを確定する
- **THEN** システムは既存の参加者と支払いをインポート内容で置き換え、最初の参加者を端数調整担当者に選択して精算結果を再計算する

#### Scenario: 有効なプレビューをキャンセルする
- **WHEN** ユーザーがCSVプレビューをキャンセルする
- **THEN** システムは既存の参加者、支払い、端数調整担当者、計算結果を維持する

### Requirement: CSVテンプレートを提供する
システムは、対応している列名と `split_among` の区切り文字をインポート画面から確認できるようにしなければならない（SHALL）。

#### Scenario: CSV形式を確認する
- **WHEN** ユーザーがCSV形式のヘルプを要求する
- **THEN** システムは必須ヘッダーと1行以上の有効な支払い例を含むサンプルを表示またはダウンロードする
